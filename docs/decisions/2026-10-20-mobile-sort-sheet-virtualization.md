# 전국도감 종족값 모바일: 정렬 시트 + 가상화 (2026-10-20)

2026-10-19의 두 결정(`2026-10-19-sort-ui.md`의 모바일 머리글 정렬, `2026-10-19-list-rendering.md`의 전체 그리기)을
이 페이지(`/pokedex/national-base-stats`, v4)에서 바꾼다. 실기기 배포 후 확인한 결과다.

## 실기기에서 나온 문제

- 머리글 한 줄에 정렬 버튼 7개(H A B C D S 총합)가 너무 빽빽하다. 글자를 줄여도 답답하다.
- 전체 그리기 정렬이 대개는 괜찮지만, 가끔 크게 늦어져 쓸 수 없는 수준이다.

## 선택

- **모바일(본문 @5xl 미만) 정렬은 바텀시트**로 한다. 결과 줄 오른쪽 버튼으로 연다 (배경 없는 글자 + ⌄: `도감번호순`, `이름 반대순`, `특공 높은 순`).
  - 시트 (/pokedex/national 정렬 시트처럼 단순하게. 처음 만든 타일 2열은 난잡해 버렸다):
    - 정렬 기준: radio 2열 (점 + 글자, 칸 배경 없음). [도감번호 | 이름] [HP | 공격] [방어 | 특수공격] [특수방어 | 스피드] [총합]. 총합은 끝 (카드 칸·데스크탑 열도 총합이 끝).
      시트·결과 줄 버튼·데스크탑 머리글은 정식 이름, 카드 칸만 줄인 이름(특공·특방)이다. 카드 칸은 스크린리더에 정식 이름을 읽힌다
      (두 줄 '특수/공격'은 카드가 16px씩 높아지고 오히려 덜 읽혀 버렸다).
    - 정렬 순서: radio 2열, 아이콘 없음 (세그먼트는 쓰지 않는다. ⌃⌄는 펼치기로도 읽혀 뺐다). 기준과는 구분선으로 나눈다.
      첫 방향이 왼쪽: [번호순 | 번호 반대순] (결과 줄 버튼은 `도감번호순`·`도감번호 반대순`), [이름순 | 이름 반대순], [높은 순 | 낮은 순].
      번호·이름은 기준 이름이 겹쳐도 붙인다: 고른 글자가 결과 줄 버튼에 그대로 나오고, '역순'만으로는 무엇의 반대인지 애매했다.
      '반대순'은 포켓몬 공식 도감의 표현. 이름은 고른 언어 기준으로 정렬하지만 글자는 언어와 상관없이 같다
      (버린 안: '1 → 1025'·'가 → 하' 같은 범위 표기, '정순/역순', '순서대로/역순', '오름차순/내림차순').
  - 고르면 반영하고 닫는다 (쇼핑앱 정렬 시트와 같은 흐름). 아래엔 [닫기]만. 초기화는 도감번호를 고르는 것과 같아 뺐다.
    - 많이 쓰는 "기준 + 첫 방향"은 2번(열기 → 기준), 방향까지 바꾸면 4번(열기 → 기준 → 열기 → 방향)으로 열어 두는 방식보다 적거나 같다.
    - "적용하기"는 쓰지 않는다. 바로 반영되는 필터와 어긋난다.
  - 키보드: radio는 화살표 키로 옮기면 바로 선택된다(표준). 이때 닫으면 바로 옆 항목밖에 못 고르므로
    화살표 키는 반영만 하고 시트를 둔다. 닫기는 터치·클릭(click의 detail > 0)·Space·Enter에서만.
    (base-ui radio는 화살표로 옮길 때도 click을 내보내는데 detail이 0이다)
    가상화 이후 정렬이 가볍고 URL은 replace라 화살표로 훑으며 반영돼도 괜찮다.
  - 정렬 선택지가 적은 페이지(방향 포함 4개 이하, 예: /pokedex/national)는 기준·방향을 합친 목록 하나로 둔다 (2열: 줄 = 기준, 칸 = 방향).
- **카드에 머리글이 없다.** 능력치 칸마다 이름(text-xs)을 숫자 위에 둔다. 행 높이 117 → 137px.
- **데스크탑(@5xl 이상)은 그대로** 10열 테이블 + 머리글 정렬.
- **그리기 방식은 본문 폭으로 나눈다** (`useIsWideContainer`, `?list=auto|full|virtual`).
  - 좁은 본문(카드): 가상화(`@tanstack/react-virtual`, window 기준). 실기기에서 전체 그리기 정렬이 가끔 크게 늦었다.
  - 넓은 본문(테이블): 전체 그리기. 데스크탑은 원래 성능 문제가 없었고(M2 정렬 약 90ms), 브라우저 찾기(Ctrl+F)가 전부 된다.
  - 처음엔 "두 폭 모두 가상화"로 했었다(그리기 방식 하나로 관리, 1024px 경계에서 방식이 바뀌며 위치가 틀어질 수 있음).
    성능상 필요가 아니라 관리 편의였고 데스크탑 Ctrl+F를 잃어 되돌렸다. 경계를 넘나드는 경우(창 크기 조절·태블릿 회전)는 드물다.
  - 첫 렌더는 좁은 본문(가상화)으로 그리고 페인트 전에 실제 폭으로 바꾼다 (모바일에서 1,248행을 한 번이라도 그리지 않게).

## 선택된 상태 = primary

정렬 시트 radio·필터 checkbox가 primary라, "지금 무엇으로 정렬 중인지" 표시도 primary로 맞춘다.

- 모바일 카드: 정렬 중인 칸의 이름·숫자를 `text-primary-text` + 숫자 굵게. 도감번호순·이름순이면 No.번호·이름을 primary 글자색으로. 배경은 없앤다 (회색 칩 → 버림. 옅은 primary 칩은 1,248장에 걸쳐 시끄러워 버림).
- 데스크탑 머리글: 업비트 같은 거래 사이트처럼 ▲▼ 삼각형을 늘 두고, 지금 기준이면 그 방향 삼각형과 열 이름을 primary로.
  - 머리글 버튼은 글자 폭(fit), 열 정렬을 따른다 (숫자 열은 오른쪽). w-full(이름 왼쪽·삼각형 오른쪽 끝)도 시험했으나 되돌렸다.
  - 삼각형은 아이콘 대신 CSS 테두리(8×5px, 위아래 3px 간격. 10×6px은 커 보여 되돌렸다). hover로 색이 바뀌지 않는다. 방향은 aria-sort가 알린다.
  - 머리글은 줄이지 않은 이름(특수공격·특수방어). 두 열 최소 폭을 80 → 100px로 넓히고 HP·총합·공격·방어·스피드에서 같은 만큼 줄여
    최소 폭 합계를 유지했다 (본문 1024px에서 넘치지 않게).
  - 색만으로 방향을 구분하는 약점은 열 이름도 primary로 칠해 "어느 열"을 글자가 알리게 해 줄였다.
- 결과 줄 정렬 버튼·시트 radio 줄은 배경색 없이 hover(마우스 기기만)·누름 때 opacity-70.

## 이름 언어 (?lang=)

- 고른 언어 하나가 **이름 표시·검색 대상·이름순 정렬**을 함께 정한다 (한국어·영어·일본어).
  - 예전엔 세 언어로 찾고 한글로만 보여 줘서, 영어로 찾으면 다른 이름이 나와 헷갈렸다.
  - 도감 번호 검색은 언어와 상관없다. 일본어는 히라가나로 쳐도 가타카나 이름이 찾힌다.
  - 폼은 한국어처럼 약칭이 있을 때만 붙인다: 나옹 (가라르) / Meowth (Galarian) / ニャース (ガラルのすがた).
- 위치: 검색창 안 왼쪽 버튼 `[한 ⌄ │ 🔍 …]` (전화번호 국가 코드처럼 '이 검색창의 언어').
  - 누르면 md 미만은 바텀시트, 이상은 팝오버. radio 목록(오른쪽에 그 언어 예시 이름) + 고르면 닫힘 (정렬 시트와 같은 규칙).
  - 세그먼트 [한|EN|日]는 쓰지 않는다 (사용자 선호). 결과 줄에 두면 344px에서 넘쳤다.
- URL에 둔다 (`?lang=en|ja`, 한국어는 안 씀). 검색 결과가 언어에 따라 달라 공유 링크가 같은 결과를 보이게.
- 고른 언어로 0건이고 다른 언어로는 찾히면 빈 화면에 "영어 이름으로는 3마리가 있어요 · [영어로 보기]".
  몰래 다른 언어까지 찾지 않고 알린다.
- 좁은 화면의 필터 아이콘 버튼은 뺐다. /pokedex/national처럼 칩 줄로 다시 만들 때까지 좁은 화면엔 필터가 없다.

## 스크롤 위치

목록은 서버 HTML에 없다(nuqs의 `useSearchParams`로 클라이언트 렌더로 넘어감). 그래서 브라우저가 스크롤을 복원하는 시점엔 문서가 짧다.

| 상황 | 처리 |
|---|---|
| 새로고침 / 다른 사이트에서 브라우저 뒤로 | `useReloadScrollRestoration`: 떠날 때(pagehide·숨김) 위치를 URL별로 sessionStorage에 저장. 문서 첫 마운트이고 탐색 종류가 reload·back_forward이며 주소가 그 문서일 때만 복원 |
| 같은 문서 안 뒤로 가기 | Activity가 DOM을 보존해 Next가 복원 (손대지 않음) |
| 링크로 다시 들어옴 | Next가 맨 위로. 복원하지 않음 |

가상화 라이브러리(virtual-core 3.17) 때문에 한 일:
- `scrollToFn`을 비웠다. 라이브러리는 마운트하거나 Activity로 다시 보일 때 기억한 위치로 window를 옮긴다. 이것 때문에 새로고침 복원이 0으로 덮이고, 링크로 들어오면 예전 위치로 끌려갔다.
- 마운트하거나 다시 보일 때 `scrollOffset`을 현재 `scrollY`로 맞춘다. 라이브러리는 scroll 이벤트로만 위치를 안다. 맞추지 않으면 링크로 들어와 맨 위에 있어도 예전 위치의 행을 그려 빈 화면이 된다.
- 복원 직후 scroll 이벤트를 직접 보낸다. 불러오는 중의 스크롤은 이벤트가 오지 않을 때가 있다.

## 다른 목록 페이지로 넓히기 (2026-10-20)

- **모바일(좁은 본문)에서는 표를 쓰지 않는다.** 특성·기술 목록도 카드 + 결과 줄 정렬 버튼 + 정렬 시트로 통일한다.
  - 특성은 언어 선택으로 이름이 한 줄이 되면 #·이름·등장 3열 표가 344px에 들어가고 머리글 정렬도 가능했다
    (`/ability?view=table` 미리보기로 확인 후 지움). 그래도 모바일 표를 고집할 이유가 크지 않고,
    페이지마다 정렬 방식이 다른 것보다 **"모바일 정렬은 늘 결과 줄 버튼 → 시트"** 한 가지가 낫다고 판단했다.
  - 버린 안: "목록 모양이 정렬 방식을 정한다(표는 머리글, 카드는 시트)". 규칙으로는 성립하지만 페이지마다 정렬 위치가 달라진다.
- **데스크탑은 표 + 머리글 정렬** 그대로.
- 특성·기술도 검색창 앞 이름 언어 선택을 쓴다 (고른 언어로 이름 표시·검색·이름순). 2곳 이상에서 쓰게 되면 `_features`로 옮긴다.

## 포켓몬 정체성 묶음: 이미지 · 도감번호 · 이름 / 모습 · 타입 (2026-10-22)

여러 곳에서 쓸 묶음이라 카드와 테이블을 **같은 순서·같은 요소**로 둔다.

| | 모바일 카드 (@5xl 미만) | 데스크탑 테이블 (@5xl 이상) |
|---|---|---|
| 1 | 스프라이트 타일 64px | **도감번호 열** = [스프라이트 \| 번호] 두 칸 (`64px 44px`) |
| 2 | 번호 `0052` (`No.` 없이) | 머리글 '도감번호 ▴▾'가 두 칸에 걸침, 왼쪽 정렬 |
| 3 | 이름 / 모습 두 줄 | 이름 / 모습 두 줄 |
| 4 | 타입 | 타입 |

- **이름 / 모습 두 줄.** 모습은 읽어야 하는 정보라 `text-sm`(`foreground/70`). 정식 이름(가라르의 모습 · Galarian · ガラルのすがた)을 쓰고, 약칭이 있는 폼(`shortKo`)에만 붙인다.
  - 카드: 글자 묶음 이름 21 + 2 + 모습 20 = 43px. 타일 64px 안이라 카드 137px 그대로.
  - 테이블: 이름 칸만 위아래 여백 12px(12 + 21 + 20 + 12 = 65)로 행 69px 안.
- **번호에 `No.`를 붙이지 않는다.** 카드에서 이름 칸이 21px 넓어지고(375px에서 136px), 테이블 열과 같은 모양이 된다. 무엇의 번호인지는 결과 줄 '도감번호순'과 테이블 머리글이 알린다.
- **테이블 도감번호 열:** 스프라이트(열 왼쪽 여백 14) 바로 뒤에 번호를 8px로 붙여 한 덩어리로 읽힌다 (pokemondb의 # 열과 같은 모양). 번호는 네 자리 고정이라 오른쪽 정렬로 얻는 게 없어 왼쪽 정렬. 머리글은 '#' 대신 '도감번호'.
- **감수:** 가장 긴 모습(Paldean Combat Breed 등)은 카드에서 말줄임된다(375px). 344px에서는 이름도 잘릴 수 있다.
- 버린 안 (v4에 `?formline=`로 넣어 비교한 뒤 지움):
  - 한 줄 '이름 (모습)': 영어·일본어에서 길어 잘린다.
  - 세 줄 [번호 / 이름 / 모습]을 64px 타일 옆에: 모습 `text-xs`는 읽기에 작고, `text-sm`은 줄 간격 없이 꽉 차 답답하다.
  - 이름 / '번호 · 모습' (번호를 이름 아래 정보 줄로): 번호 위치가 테이블과 다르다.
  - 타일 72px + 세 줄: 카드가 8px 커지고 모습 유무로 이름 위치가 오르내린다.
